# Echolingo — Plan 5: Azure Deploy (azd + AVM + Azure OpenAI + SAMI)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Provision everything Echolingo needs in the `Echolingo` Azure subscription via `azd up`, deploy the Function App + Static Web App from this repo, and have a publicly reachable URL serving real Greek lessons generated by **Azure OpenAI** using only **system-assigned managed identity** (SAMI) — zero API keys anywhere in infra or app config.

**Architecture:** Bicep composed of **Azure Verified Modules** (`br/public:avm/res/...`). One Azure OpenAI resource in West Europe with two **GlobalStandard** deployments (`gpt-5.4-mini` for LLM, `tts` for TTS) at 150K tokens/min quota. A **Flex Consumption** Linux Function App with SAMI gets the `Cognitive Services OpenAI User` role on the AOAI resource, plus `Storage Blob Data Contributor` and `Storage Queue Data Contributor` on the storage account (no `AzureWebJobsStorage` connection string — Functions v4 supports identity-based runtime storage on Flex Consumption). A linked **Static Web App** serves the frontend and proxies `/api/*` to the Function App automatically. App Insights uses workspace-based telemetry. The existing `OpenAiLlmEngine` / `OpenAiTtsEngine` are refactored to take an Azure config (endpoint + token provider) instead of an API key; local dev authenticates via `DefaultAzureCredential` which falls through to `az login`.

**Tech Stack:** Plan 1–4 + Azure Bicep, Azure Verified Modules (AVM), `azd` v1.23+, `@azure/identity` (^4.x), `azurerm` resource provider, GitHub Actions OIDC for CI deploys.

## Conventions

- All Bicep modules use AVM (`br/public:avm/res/...`) with pinned versions. Use `azd provision` (not `az deployment`) to deploy; azd injects `AZURE_ENV_NAME`, `AZURE_LOCATION`, `AZURE_PRINCIPAL_ID` automatically.
- The Function App and all clients (Blob/Queue/AOAI) authenticate exclusively via SAMI. Local dev uses `DefaultAzureCredential` which finds your `az login` token.
- AOAI resource lives in **West Europe** with **GlobalStandard** deployments — capacity isn't pinned to one region.
- `WEBSITE_CONTENTAZUREFILECONNECTIONSTRING` and `AzureWebJobsStorage` connection strings are NOT set; instead `AzureWebJobsStorage__accountName` plus role assignments give identity-based access.

```bicep
param environmentName string

@description('Location for AOAI (e.g. westeurope).')
param location string

@description('Tags.')
param tags object

@description('LLM model name; deployment name will match.')
param llmModelName string

@description('TTS model name; deployment name will match.')
param ttsModelName string

@description('Quota per deployment in thousand tokens per minute.')

    name: accountName
    location: location
    tags: tags
    kind: 'OpenAI'
    sku: 'S0'
    customSubDomainName: accountName
    disableLocalAuth: true        // Entra ID only — no API keys
    publicNetworkAccess: 'Enabled'
    deployments: [
      {
        name: llmModelName
        model: {
          format: 'OpenAI'
          name: llmModelName
        }
        sku: {
          name: 'GlobalStandard'
          capacity: quotaTpm
        }
        versionUpgradeOption: 'OnceCurrentVersionExpired'
      }
      {
        name: ttsModelName
        model: {
          format: 'OpenAI'
          name: ttsModelName
        }
        sku: {
          name: 'GlobalStandard'
          capacity: quotaTpm
        }
        versionUpgradeOption: 'OnceCurrentVersionExpired'
      }
    ]
    // Local-dev access: grant deployer the OpenAI User role on this account.
    roleAssignments: empty(principalId) ? [] : [
      {
        principalId: principalId
        roleDefinitionIdOrName: 'Cognitive Services OpenAI User'
        principalType: 'User'
      }
    ]
  }
}

output endpoint string = openai.outputs.endpoint
output accountName string = openai.outputs.name
output accountResourceId string = openai.outputs.resourceId
output llmDeployment string = llmModelName
output ttsDeployment string = ttsModelName
```

`disableLocalAuth: true` forces all callers to use Entra ID tokens — no key auth ever works on this resource. The `roleAssignments` array gives the deploying user (`AZURE_PRINCIPAL_ID` from azd) access for local development.

```ts
    return new BlobRateLimitStore({
      endpoint: config.blobEndpoint,
      containerName: config.rateLimitContainer,
    });
  }
  return new BlobRateLimitStore({
    connectionString: config.storageConnectionString!,
    containerName: config.rateLimitContainer,
  });
}

function buildQueue(config: Config): QueueClient {
  if (config.queueEndpoint) {
    return new QueueClient({
      endpoint: config.queueEndpoint,
      scriptGenQueue: config.scriptGenQueue,
      ttsSentenceQueue: config.ttsSentenceQueue,
    });
  }
  return new QueueClient({
    connectionString: config.storageConnectionString!,
    scriptGenQueue: config.scriptGenQueue,
    ttsSentenceQueue: config.ttsSentenceQueue,
  });
}

export function getContext(): ApiContext {
  if (cached) return cached;
  const config = loadConfig();
  cached = {
    config,
    lessons: buildLessons(config),
    audio: buildAudio(config),
    queue: buildQueue(config),
    llm: buildLlm(config),
    tts: buildTts(config),
    rateLimits: buildRateLimits(config),
    telemetry: createTelemetry({ connectionString: config.appInsightsConnectionString }),
  };
  return cached;
}

export function setContextForTests(override: ApiContext | undefined): void {
  cached = override;
}
```
